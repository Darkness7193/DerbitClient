    git

Установка:

    git clone https://github.com/Darkness7193/DerbitClient DerbitClient

    uv sync &&
    mv example.env .env &&
    sudo docker compose up --build -d

    # Подождать 5-15с

    sudo docker compose exec rabbitmq rabbitmqctl add_user rabbitmquser password &&
    sudo docker compose exec rabbitmq rabbitmqctl set_permissions -p / rabbitmquser ".*" ".*" ".*" &&
    sudo docker compose exec -it app uv run alembic upgrade head &&
    sudo docker compose up --build


Доступный API:

    1. Метод для тестов. Получает и сохраняет tickers_data объект:
        GET http://127.0.0.1:8000/fetch_ticker?ticker=BTC-PERPETUAL
        ticker: str. Название валюты. Список доступных значений можно узнать на
        https://docs.deribit.com/api-reference/market-data/public-get_instruments

    2. Получение всех сохраненных данных по указанной валюте:
        GET http://localhost:8000/get_all_currency_data?ticker=BTC-PERPETUAL
        ticker: str. Название валюты. Список доступных значений можно узнать на
        https://docs.deribit.com/api-reference/market-data/public-get_instruments

    3. Получение последней цены валюты:
        GET http://localhost:8000/get_last_currency_price?ticker=BTC-PERPETUAL
        ticker: str. Название валюты. Список доступных значений можно узнать на https://docs.deribit.com/api-reference/market-data/public-get_instruments

    4. Получение цены валюты с фильтром по дате:
        GET http://localhost:8000/get_currency_price?ticker=BTC-PERPETUAL&start_iso_date=2020-01-01T00:00:00Z
        ticker:         str.      Название валюты. Список доступных значений можно узнать на
            https://docs.deribit.com/api-reference/market-data/public-get_instruments
        start_iso_date: iso_date. Начальная дата фильтрования по датам
        end_iso_date:   iso_date. Конечная дата фильтрования по датам

    Смена запрашиваемых валют в src/app/tasks fetch_and_save_tickers. По хорошему пришить бы еще один апи


Архитектурные решения:
    1. Управление зависимостями Python:
        В проекте используется uv для управления зависимостями и виртуальными окружениями. Зависимости объявлены в pyproject.toml с указанием минимальных версий (>=), что позволяет устанавливать более новые совместимые версии библиотек

    2. FastAPI для прикладного уровня:
        FastAPI используется для создания HTTP API приложения. Он обеспечивает валидацию запросов, автоматическую генерацию документации API и интеграцию с моделями Pydantic. Uvicorn выступает в качестве ASGI-сервера для запуска приложения

    3. Асинхронный ввод-вывод (Asynchronous I/O)
        Там где это уместно используются асинхронные библиотеки для повышения эффективности операций ввода-вывода. aiohttp обрабатывает асинхронные HTTP-запросы к API Deribit, а поддержка asyncio в SQLAlchemy и библиотека asyncpg обеспечивают асинхронный доступ к базе данных
        Такой подход позволяет выполнять сетевые операции и операции с базой данных без ненужной блокировки цикла событий (event loop)

    4. Интеграция с API Deribit:
        Приложение получает рыночные данные через HTTP-запросы к API Deribit. aiohttp используется для асинхронных запросов, а requests остаётся доступной для синхронных HTTP-операций когда это необходимо
        Разделение взаимодействия с внешним API и сохранения данных упрощает поддержку и тестирование кода

    5. PostgreSQL в качестве базы данных:
        PostgreSQL используется для постоянного хранения данных тикеров. Она обеспечивает надёжное хранение реляционных данных и поддерживает структурированные запросы для получения исторических рыночных данных
        Драйвер asyncpg используется для асинхронных операций с базой данных, а psycopg[binary] поддерживает синхронные подключения к PostgreSQL и инструменты, требующие драйвера Psycopg

    6. SQLAlchemy в качестве ORM:
        SQLAlchemy используется для определения моделей базы данных и управления операциями с ней. ORM преобразует объекты Python в записи реляционной базы данных, уменьшая необходимость писать SQL-запросы вручную для стандартных операций
        Асинхронный интерфейс SQLAlchemy используется для работы с базой данных в асинхронном коде приложения

    7. Alembic для миграций базы данных:
        Alembic управляет изменениями схемы базы данных с помощью версионируемых скриптов миграций. Это позволяет воспроизводить изменения схемы и поддерживать согласованную структуру базы данных в средах разработки и развёртывания

    8. Celery для фоновых задач:
        Celery используется для выполнения фоновых задач независимо от обработки HTTP-запросов. Сбор данных тикеров можно запускать по расписанию, получая рыночные данные через регулярные интервалы без блокировки API
        Такое разделение упрощает сопровождение проекта и позволяет масштабировать фоновую обработку независимо от приложения

    9. RabbitMQ в качестве брокера сообщений:
        RabbitMQ используется в качестве брокера сообщений между приложением и рабочими процессами Celery. Он передаёт сообщения с задачами и отделяет отправку задач от их выполнения
        Такая архитектура позволяет рабочим процессам выполнять задачи независимо от API-сервиса

    10. Pydantic Settings для конфигурации:
        pydantic-settings используется для загрузки и проверки конфигурации приложения, включая учётные данные базы данных, строки подключения и настройки внешних сервисов.
        Переменные окружения и файлы окружения позволяют отделить конфигурацию от программного кода и избежать жёсткого прописывания учётных данных непосредственно в коде

    11. Интеграция с Docker:
        Python SDK для Docker доступен для программного взаимодействия с Docker. Контейнеризация обеспечивает единообразную среду выполнения и упрощает совместный запуск приложения и его зависимостей

    12. Типизация и удобство сопровождения:
        celery-types предоставляет информацию о типах для Celery, улучшая статический анализ кода и поддержку в редакторах. Аннотации типов и чёткое разделение компонентов приложения делают код более понятным, упрощают его сопровождение и дальнейшее расширение

    13. Разделение ответственности:
        В приложении HTTP-эндпоинты, взаимодействие с внешним API, выполнение фоновых задач, модели базы данных и конфигурация разделены на отдельные компоненты. Такая модульная структура уменьшает связанность компонентов и упрощает их тестирование и замену
